## Outstanding practical gates

Fresh-install Accessibility/Phone consent, the complete policy video, native
Settings access during the eight-second hold and disablement are not yet
verified for the final candidate. Hosted failure captures showed that stock
`uiautomator dump` can suppress the service under test; the observer is being
replaced rather than treating its hierarchy as a production failure verdict.
API 35/36 call scenarios must also pass after final tooling integration.

Actual native libraries pass LOAD and APK ZIP alignment checks. Their RELRO
layout fails the literal documented formula; compatibility-off runtime testing
is pending. An earlier test forced an unsupported pre-API-34 iterator on API
36 and crashed, so it does not prove the app's supported path crashes. The
replacement tests the supported native conic conversion path. Any successful
x86_64 emulator result will not establish ARM64 hardware behavior.

The current 1080×2400 RGBA policy captures are test evidence, not uploadable
Play screenshots. A separate actual 1080×1920 RGB JPEG packet is in preparation.
The listing gate now checks screenshot format, count, dimensions and side ratio
and reports absent captures explicitly.

Authenticated Play Console evidence establishes a personal account with
identity documents uploaded and Google's verification pending. App creation is
disabled until account verification completes. Phone verification follows
identity approval. There is no app draft, release upload, review submission or
store listing yet. F-Droid remains on the owner's chosen wait-for-rotation path
with Android 8 retained. Apple/App Store work was discontinued by the owner.
